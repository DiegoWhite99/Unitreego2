1 · Flujo de conexión — Pipeline de 4 pasos

Se rediseñó el panel principal de src/index.html para mostrar un pipeline compacto y jerárquico que guía al operador paso a paso:

3 · Agente IA Diver — correcciones

Problema: respuesta "no puedo saludar"

Al decir "hola", gpt-4o-mini interpretaba el saludo como una orden de gesto físico, llamaba la tool saludar, esta fallaba con "El robot no está conectado", y el modelo respondía con una disculpa. Esto violaba la Regla 1 del identity del agente.

Corrección en core/agents/identity/04_rules.md:

  • Se agregó la Regla 1b: distingue saludo conversacional ("hola", "hey") de comando físico ("saluda con la pata").
  • Saludo conversacional → respuesta directa en chat, sin invocar ningún tool.
  • La frase "no puedo" queda explícitamente prohibida incluso cuando el robot está desconectado.

Botón de acción directa (bypass IA)

El botón "Modo serio" en console/console_IA.html tenía un texto que gpt-4o-mini rechazaba por políticas de contenido. Se implementó un campo direct: true en la definición del botón: cuando está activo, el texto se inyecta directamente en la consola y el TTS lo lee sin pasar por ningún modelo.

4 · Autoroute — mapa en tiempo real + voz

4.1 Heat en tiempo real

El handler lidar_points de src/js/autoroute.js ahora acumula los puntos XYZ del lidar en un Map interno (_liveHeat) usando la misma lógica de voxelización de controlRemoto.js.

Cada 15 eventos (~3 segundos a 5 Hz), el mapa hace flush: merge con route.heat, invalida el modelo offscreen y redibuja el canvas. El mapa se actualiza solo mientras el robot se mueve o gira, sin acción del usuario.

4.2 Botón 🎤 Instrucción por voz

Nuevo botón en el panel de control de autoroute. Flujo completo:

  1. Presionar 🎤 activa Web Speech API en español.
  2. El canvas del mapa se captura como JPEG (canvas.toDataURL('image/jpeg', 0.75)).
  3. Se envía a POST /api/agente/chat con campo image_b64 + contexto textual (voxels, waypoints, posición del robot).
  4. El backend decodifica la imagen y la pasa como visión multimodal a gpt-4o-mini.
  5. La respuesta se muestra en un toast y se lee con TTS usando voz masculina Google en español (pitch: 0.8, rate: 0.95).
gpt-4o-mini ve el heatmap real del lidar — columnas de colores, waypoints, trail — antes de responder a la instrucción de voz.

5 · Seguridad — migración de claves a .env

Las claves de API estaban hardcodeadas en config/config.py. Aunque este archivo ya estaba en .gitignore, se eliminó esa práctica migrando todo a un archivo .env.

Estructura nueva

unitreeWebRTC/
├── .env              ← claves reales (en .gitignore, NUNCA al repo)
├── .env.example      ← plantilla pública sin valores
└── config/
    └── config.py     ← solo lee variables de entorno vía python-dotenv

Variables en .env

VariableDescripción
ROBOT_IPIP del robot en red local
ROBOT_AES_128_KEYClave AES-128 extraída de Unitree Cloud
OPENAI_API_KEYClave de OpenAI para gpt-4o-mini
GEMINI_API_KEYClave de Google Gemini (fallback)
GEMINI_MODELModelo principal del agente
FALLBACK_MODELSCascada de modelos (PRIMARY/SECONDARY/TERTIARY)
FLASK_SECRET_KEYSecreto para sesiones Flask

config.py usa python-dotenv y degrada sin error si el paquete no está instalado (las vars del SO aplican igual). Requiere: pip install python-dotenv.
